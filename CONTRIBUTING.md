# Contributing

## Build and test

```sh
cargo test    # the pure core, no zellij needed
cargo wasm    # release build -> target/wasm32-wasip1/release/zellij-tab-namer.wasm
task ci       # what CI runs: fmt, clippy, test, wasm build (needs go-task)
```

The plugin is a pure core that turns Zellij events into a `Vec<Effect>`, plus a thin wasm-gated
adapter that runs those effects against the host. `clippy.toml` keeps the split honest by
disallowing the host functions outside that adapter, which is what makes the timing-sensitive
naming logic testable with a plain `cargo test` rather than in a live session. See
[ADR-0001](docs/adr/0001-effects-seam-with-wasm-gated-adapter.md).

[`docs/CONTEXT.md`](docs/CONTEXT.md) is the place to start: it covers the vocabulary the code and the
ADRs use, base name against rendered name, decoration, waiter, discovery query.

## The demo GIFs

Both README GIFs are recorded with [`vhs`](https://github.com/charmbracelet/vhs), through a wrapper
rather than by calling `vhs` directly:

```sh
task wasm
docs/media/demo/record.sh                      # both tapes
docs/media/demo/record.sh docs/media/demo.tape # just one
```

The wrapper exists because a take fails roughly half the time, the plugin coming up without ever
getting its permissions, and because a failed run would otherwise write a truncated GIF over the
good one. It retries, and restores the previous GIF when a tape gives up for good.

## Conventions

- Conventional commits, no emoji: `type(scope): description`.
- Everything goes through a pull request.
- `CHANGELOG.md` is generated by [git-cliff](https://git-cliff.org) (pinned by `mise`, so
  `mise trust` on first use). Don't edit it by hand.
- Releases: `task release NEW=x.y.z` bumps, regenerates the changelog, runs CI, commits, tags and
  pushes. Pushing a `v*` tag builds the wasm and publishes it as a release asset.
- `zellij-tile` is pinned by minor, which is the plugin ABI. Moving to a new minor is an explicit
  decision, and it changes the floor advertised in the README.
